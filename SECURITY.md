## Supported versions

Only the **latest release** receives security fixes. Please update before
reporting, and mention the version you tested.

## Reporting a vulnerability

**Please do not open a public issue for security problems.**

Report privately through GitHub:
[**Report a vulnerability**](https://github.com/sarmadiq9090-coder/local-ai-chat/security/advisories/new)
(repository → *Security* tab → *Report a vulnerability*).

Please include:

- the app version and Windows version,
- what an attacker can do and what they need (e.g. "a web page open in the
  user's browser", "a malicious model response", "a crafted file"),
- steps to reproduce or a proof of concept.

This is a hobby project maintained in spare time. You can expect an initial
reply within about a week. Once a fix is released, the advisory will be
published and you will be credited unless you prefer otherwise.

## Security model and scope

Local AI Chat is a local, single-user desktop app. Useful context:

- **Local server, loopback only.** The built-in HTTP server binds to
  `127.0.0.1` on a local port and is never exposed to the network. It has no
  authentication because only processes on the same machine can reach it.
- **Talks only to your Ollama.** Requests are proxied to the Ollama URL in
  Settings (default `http://127.0.0.1:11434`). No telemetry or third-party
  services.
- **Model output is untrusted.** Markdown is rendered with an escape-first
  renderer; raw HTML from the model is not inserted into the app.
- **Live preview is sandboxed.** HTML/JS run from the chat executes in an
  `<iframe sandbox>` **without** `allow-same-origin`, so it has an opaque
  origin and cannot read the app's DOM, storage or call its API with the app's
  origin.
- **Navigation lock.** The app window only navigates within its own local
  origin; external links are handed to the default browser.

### In scope

- Ways for a **web page in the user's normal browser** (or another
  non-privileged origin) to read or change data through the local server
  (CSRF, DNS rebinding, missing Host/Origin checks, CORS mistakes).
- Escaping the preview sandbox, or model output / attached files leading to
  script execution in the app's origin (XSS).
- Path traversal or arbitrary file read/write through API endpoints
  (conversation IDs, export, save-to-file, assistants' knowledge files).
- Problems in the update mechanism once it ships (downloading or running an
  executable that is not the verified release asset).

### Out of scope

- Attacks that require an attacker already running code as the same Windows
  user (they can read `%APPDATA%\LocalAiChat` directly).
- Content generated by a model (wrong, harmful or offensive answers) — that is
  a property of the model, not a vulnerability in this app.
- Vulnerabilities in Ollama, the WebView2 Runtime or the models themselves:
  please report those to their respective projects.
- Pointing the Ollama URL setting at a remote/untrusted server yourself.
- Unsigned-executable / SmartScreen warnings.
